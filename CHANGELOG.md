# Changelog

- 2026-10-05
  - `stacks/30-hosts/persephone` adopts the host with `import` blocks (applied 2026-10-05: 5 imported, 0 added, 2 changed, 0 destroyed, the host's uptime unchanged; the blocks are removed now that the state holds the resources, and the stack README keeps the identifiers): the instance with its root volume, the primary network interface, the two data-volume attachments, and the Elastic Internet Protocol (IP) address (EIP) association. The image, the user data, and the instance type are ignored until the rebuild. It changes four things in place: the interface takes one Internet Protocol version 6 (IPv6) address, because the address count on the instance resource would replace the instance; termination protection is switched on; the root volume joins the daily snapshot schedule with `Backup = daily`; and `Protected = true` lands on the instance and the root volume. The key pair name comes from `op.env` because it carries an account name.
  - Checkov skips recorded with reasons in the host stack: no detailed monitoring (cost), the Elastic Block Store (EBS)-optimized launch flag left as the account holds it, and no instance profile for a host that calls no Amazon Web Services (AWS) API.
  - `stacks/20-platform` adopts the network and the durable data with `import` blocks (applied 2026-10-05: 36 imported, 12 added, 31 changed, 0 destroyed; the blocks are removed now that the state holds the resources, and the stack README keeps the identifiers): the Virtual Private Cloud (VPC), its six subnets, Internet gateway, public route table with its default route and associations, and main route table; the hosts' security group with each of its thirteen rules as its own `aws_vpc_security_group_ingress_rule` or `aws_vpc_security_group_egress_rule`; the VPC's own default group, adopted with no rules so its one egress rule goes; the Key Management Service (KMS) key and alias; the Elastic Internet Protocol (IP) address (EIP) and, as `aws_eip_domain_name`, the reverse record a provisioner used to set; and the two data volumes. It adds an Amazon-provided Internet Protocol version 6 (IPv6) /56 with a /64 per subnet, IPv6 default routes through the Internet gateway and a new egress-only gateway, an IPv6 twin of every public security-group rule plus Internet Control Message Protocol version 6 (ICMPv6) echo (the all-IPv6 egress rule is the one AWS adds by itself when a VPC gains an IPv6 block, adopted rather than created), a Data Lifecycle Manager (DLM) policy that snapshots volumes tagged `Backup = daily` at 06:00 Coordinated Universal Time (UTC) and keeps seven, `Protected = true` on the VPC, EIP, key, and volumes, and `prevent_destroy` on the same. The duplicate, unattached security group `default-vpc-cybris-net-sg` is deleted by hand before the apply rather than adopted, because the repository never plans a destroy.
  - `stacks/10-account` creates the `dlm-snapshots` service role with the Amazon Web Services (AWS)-managed DLM policy and lets `EngineerLead` pass that one role to DLM, so the platform stack applies under the engineer profile; the role's Amazon Resource Name (ARN) is an output the platform stack reads.
  - Checkov skips recorded with reasons in the platform stack: no VPC flow logs (cost), the EIP and security group attached by another stack, port 80 open for the redirect and certificate challenges, open egress for a host that fetches from anywhere, and a key policy that must name its own key with `*`.
  - The guard-rail inline policy allows `signin:AuthorizeOAuth2Access` and `signin:CreateOAuth2Token`, and `signin` joins the global-services exemption, so the Claude AWS connector can open a session under the ReadOnly permission set; before, only AdministratorAccess carried those actions.
  - The `EngineerLead` policy denies every write to Identity Center (`sso`, `sso-directory`, `identitystore`), because `PowerUserAccess` excludes IAM, Organizations, and Account but not those services, which can grant the same rights by attaching a policy to a permission set or adding a member to a group.
  - GuardDuty's `RUNTIME_MONITORING` feature declares its three agent-management sub-features as disabled, because the service reports them and a plan that leaves them undeclared offers to remove them every time.
  - The permission sets allow three regions, `us-east-1`, `us-east-2`, and `us-west-2`, chosen for a later high-availability design, and GuardDuty runs a detector in each; findings are alerted from the home region only, because an EventBridge rule can target a topic in its own region alone.
  - `stacks/10-account` is the account baseline: Identity and Access Management (IAM) Identity Center groups and the four permission sets (AdministratorAccess adopted and cut to a one-hour session, EngineerLead, ReadOnly, BillingAccess) with one guard-rail inline policy on each, because service control policies cannot bind an organization's management account; the OpenID Connect (OIDC) provider with roles for freebsd-cloud-img's publish job and aws-cybris-net's plan job; a multi-region CloudTrail into a new log bucket encrypted with Simple Storage Service (S3)-managed keys (SSE-S3); GuardDuty with only its foundational data sources; Amazon Web Services (AWS) Config adopted as it was set up, with its bucket moved from a Key Management Service (KMS) key to SSE-S3 because every object in it was already SSE-S3; IAM Access Analyzer; a Simple Notification Service (SNS) topic with GuardDuty findings of medium severity and above routed to it; the cost budget, password policy, and Elastic Block Store (EBS) encryption defaults adopted, with the default EBS key moved to the one key the account keeps.
  - Secrets and personal data (the administrator's user name, the alert address, the alternate contacts) come from `op.env`, which is ignored by git; `op.env.example` lists the variables.
  - `scripts/delete-default-vpcs.sh` deletes the default Virtual Private Cloud (VPC) in every region that has no network interface in it, dry-run by default, and skips a region it cannot reach instead of stopping. It runs before the account stack is applied because the guard rails then deny every region but the allowed ones.
  - Checkov skips are recorded with their reasons: SSE-S3 instead of KMS on the log, Config, and SNS resources; no CloudWatch Logs or SNS integration for CloudTrail; Config's deliberate exclusion of IAM types; no organization-level GuardDuty; and the IAM password policy left as it is because the account keeps no IAM users.
  - The Validate workflow gains a manual trigger.
  - `scripts/configure-github.sh` applies the repository's GitHub settings with the GitHub command line interface (CLI) and prints them with `--show`: squash-only merges with branch deletion, secret scanning with push protection, Dependabot alerts and security updates, private vulnerability reporting, Actions limited to GitHub-owned actions plus the two pinned third-party ones with a read-only default token, and a `main` ruleset requiring a pull request, the `validate` check, signed commits, and linear history. The ruleset does not require a branch to be up to date with `main`, because that re-run is the part of merging that costs time and the pull requests here are serial.
  - `.github/dependabot.yml` opens one grouped pull request a week for the pinned GitHub Actions and one for the OpenTofu provider constraints, skipping releases younger than seven days.
  - The Validate workflow runs on every pull request instead of only those that change OpenTofu files, because the ruleset requires it and a required check that can be skipped blocks the merge.
  - The shellcheck pre-commit hook is added for the new script.

- 2026-10-04
  - Repository skeleton: `.gitignore` that keeps `.terraform.lock.hcl` under version control, `.tool-versions` pinning OpenTofu 1.13.1 and tflint 0.64.0, pre-commit hooks (format, validate, tflint, Checkov, terraform-docs, secret scanning, and actionlint), a Checkov configuration that skips cross-region replication, access logging, and event notifications for the state bucket because they cost more than seven state files are worth, and a Validate workflow that runs on pull requests only and needs no Amazon Web Services (AWS) credentials; plan and apply workflows follow once the stacks are adopted and the OpenID Connect (OIDC) roles exist.
  - `stacks/00-bootstrap` adopted the existing state bucket `cybris-net-tf-bucket` with `import` blocks (applied 2026-10-04: 5 imported, 2 added, 2 changed, 0 destroyed; the import blocks are removed now that the state holds the bucket) and declares what was only ever set by hand: versioning, the public access block, and the default encryption with the AWS-managed Simple Storage Service (S3) key, which is what every object in the bucket already uses. It changes two things in place: object ownership moves from `BucketOwnerPreferred` to `BucketOwnerEnforced`, which retires access control lists the bucket never used, and a lifecycle rule expires superseded state versions after 90 days. It adds a bucket policy that denies requests without Transport Layer Security (TLS) and `prevent_destroy` on the bucket. The bucket's `Environment` tag changes from `Production` to `production` and its `Name` from `Cybris.Net S3 Bucket` to `OpenTofu state` to match the repository's tag convention.
  - The README documents the 1Password wrapper around `tofu` on the workstation, why this repository has no `op.env`, and that `AWS_PROFILE` is exported once per shell.
  - `docs/prerequisites.md` installs every tool the repository needs on macOS with Homebrew, on Fedora and Red Hat Enterprise Linux (RHEL), and on Ubuntu and Debian, and the README links to it.
  - The README keeps the five `import` blocks that adopted the bucket, with the rules for importing exactly what exists and treating any `replace` as a code error, so the procedure survives the blocks' removal from the stack.
  - The README documents how to create the state bucket on an account that has none: a first apply of `00-bootstrap` with a local backend override and no import blocks, then `tofu init -migrate-state` into the new bucket.
  - Every stack's state, `00-bootstrap`'s included, lives in the bucket under `aws-cybris-net/<stack>.tfstate` with the native S3 lock file; the previous repositories' state objects stay untouched beside them until the migration is complete.
