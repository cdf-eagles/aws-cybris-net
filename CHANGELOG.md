# Changelog

- 2026-10-04
  - Repository skeleton: `.gitignore` that keeps `.terraform.lock.hcl` under version control, `.tool-versions` pinning OpenTofu 1.13.1 and tflint 0.64.0, pre-commit hooks (format, validate, tflint, Checkov, terraform-docs, secret scanning, and actionlint), a Checkov configuration that skips cross-region replication, access logging, and event notifications for the state bucket because they cost more than seven state files are worth, and a Validate workflow that runs on pull requests only and needs no Amazon Web Services (AWS) credentials; plan and apply workflows follow once the stacks are adopted and the OpenID Connect (OIDC) roles exist.
  - `stacks/00-bootstrap` adopted the existing state bucket `cybris-net-tf-bucket` with `import` blocks (applied 2026-10-04: 5 imported, 2 added, 2 changed, 0 destroyed; the import blocks are removed now that the state holds the bucket) and declares what was only ever set by hand: versioning, the public access block, and the default encryption with the AWS-managed Simple Storage Service (S3) key, which is what every object in the bucket already uses. It changes two things in place: object ownership moves from `BucketOwnerPreferred` to `BucketOwnerEnforced`, which retires access control lists the bucket never used, and a lifecycle rule expires superseded state versions after 90 days. It adds a bucket policy that denies requests without Transport Layer Security (TLS) and `prevent_destroy` on the bucket. The bucket's `Environment` tag changes from `Production` to `production` and its `Name` from `Cybris.Net S3 Bucket` to `OpenTofu state` to match the repository's tag convention.
  - The README documents the 1Password wrapper around `tofu` on the workstation, why this repository has no `op.env`, and that `AWS_PROFILE` is exported once per shell.
  - `docs/prerequisites.md` installs every tool the repository needs on macOS with Homebrew, on Fedora and Red Hat Enterprise Linux (RHEL), and on Ubuntu and Debian, and the README links to it.
  - The README keeps the five `import` blocks that adopted the bucket, with the rules for importing exactly what exists and treating any `replace` as a code error, so the procedure survives the blocks' removal from the stack.
  - The README documents how to create the state bucket on an account that has none: a first apply of `00-bootstrap` with a local backend override and no import blocks, then `tofu init -migrate-state` into the new bucket.
  - Every stack's state, `00-bootstrap`'s included, lives in the bucket under `aws-cybris-net/<stack>.tfstate` with the native S3 lock file; the previous repositories' state objects stay untouched beside them until the migration is complete.
